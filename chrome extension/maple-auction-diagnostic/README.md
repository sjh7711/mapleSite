# 메이플 경매장 판매완료 수집기 0.9.2

## 0.9.2 수정 사항

- 앱솔랩스 아처 등 묶음 검색에서도 요청하지 않은 화면의 방어구·장신구 표시 때문에 저장이 거절되지 않도록 수정했습니다. 검색어·페이지·정렬·스타포스·잠재·가격 검증은 유지합니다.
- 저장 전 검증에 실패하면 어떤 조건이 예상값과 달랐는지 표시합니다. 검색 키와 원본 요청 URL은 로그에 포함하지 않습니다.
- 0.9.0의 VM 자동 저장 및 재전송 기능을 유지합니다.

업데이트할 때는 기존 확장 폴더에 파일을 덮어쓴 뒤 `chrome://extensions`에서 **새로고침**하세요. 경매장 탭도 새로고침하고 수집 관리자 창을 다시 열어야 새 코드가 적용됩니다. 같은 설치를 유지하면 수집 진행도와 VM 전송 대기열을 이어서 사용합니다.

메이플스토리 웹 경매장의 판매완료 검색이 반환하는 구조화된 장비 응답을 읽어 시세 학습용 원본으로 저장하는 Chrome 확장 프로그램입니다. 이미지·OCR·마우스 hover 툴팁 판독은 사용하지 않으며, 검증된 151종 고정 카탈로그와 분류별 고잠재 검색을 포함한 185개 물리 검색을 순회합니다.

## v0.8 운영 규칙

| 항목 | 동작 |
|---|---|
| 조사 대상 | 고정 장비 151종: P1 141종, P2 10종 |
| 검색 화면 | 판매완료(`/price`)만 사용 |
| 검색 방식 | 정확한 장비명 또는 검증된 세트 접두어 부분검색, 최근 거래순(`TRADE_DATE_DESC`) |
| 검색 한도 | 사이트 계정별 일반 98회 + 복구 예비 2회, 최대 100회 |
| 페이지 크기 | `60개씩 보기`를 검증하고, 결과 화면의 정확한 숫자 버튼을 눌러 최대 500건까지 순회 |
| 원본 저장 | 검색 결과 한 페이지마다 `capture.v2` 문서 한 줄인 JSONL |
| 중단 복구 | 페이지 단위 체크포인트와 미저장 페이지를 로컬 DB에 보관하고 재개 |

모든 새 작업은 장비명이나 조건이 든 URL을 만들지 않습니다. 현재 탭이 시세 탭이 아니면 상단 **시세** 탭을 누르고, **초기화 → 정확한 장비명 선택 또는 검증된 접두어 입력 → 가격 입력 → 스타포스 입력 → 잠재·합산 입력 → 필터 검색 → 60개씩 보기 확인·선택** 순서로 화면을 직접 조작합니다. 새 결과가 `api.mskr.nexon.com`에서 반환한 `/tool-tip` 응답을 검증한 뒤 첫 페이지를 저장하고, 후속 페이지는 페이지네이션 안의 정확한 숫자 버튼을 한 번 눌러 이동합니다. URL의 `page`를 직접 바꾸거나 비공개 API로 다음 페이지를 요청하지 않습니다. 이동한 모든 페이지에서 검색 키·필터·정렬·60개 보기·검색 횟수와 화면 매물의 순서·이름·가격을 구조화 응답과 다시 대조합니다. 응답 조회는 화면 동작으로 이미 수신한 캡처만 읽으며, 응답 본문을 놓친 경우에는 같은 결과 페이지를 새로고침해 한 번 더 받을 뿐 비공개 API나 hover로 우회하지 않습니다. 화면에 0건이 표시돼도 구조화 응답의 빈 목록을 확인해야만 빈 결과로 저장합니다. 검색 키·계정 ID·캐릭터 ID와 원본 요청 URL은 메모리 밖으로 내보내거나 원본 파일에 저장하지 않습니다.

오늘 검색 사용량은 경매장 상단의 `검색 횟수 n / 100` 표시를 실행 전과 각 작업 사이에 다시 읽어 동기화합니다. 사이트 표시가 100회면 새 검색을 시작하지 않습니다. 로그인 계정을 바꿔 횟수가 안정적으로 낮아지면 새 한도 세션으로 자동 전환하며, **새 계정 동기화** 버튼으로 현재 계정의 표시값을 직접 재확인할 수도 있습니다. 완료된 검색과 저장된 매물은 계정 전환 때 초기화하지 않습니다.

연속된 **필터 검색** 클릭은 최소 10초 간격으로 실행합니다. 0건 결과나 수집 오류 뒤에도 마지막 클릭 시각을 체크포인트에 보존해 다음 검색이 즉시 실행되지 않으며, 같은 검색 안의 숫자 페이지 이동과 현재 페이지 새로고침에는 이 간격을 적용하지 않습니다.

확장을 업데이트하거나 `chrome://extensions`에서 새로고침하면 이미 열려 있던 관리자 창은 더 이상 사용할 수 없습니다. 기존 창은 수집을 중단하고 다시 열기 안내를 표시하며, 새 관리자 창에서 저장된 페이지 체크포인트를 복구합니다.

`최근 거래순`은 첫 매물 하나만 저장한다는 뜻이 아닙니다. 단일 페이지 정책은 최대 60개, 전 페이지 정책은 같은 검색 결과에서 최대 500개 매물을 저장합니다.

## 설치 또는 업데이트

1. Chrome에서 `chrome://extensions`를 엽니다.
2. **개발자 모드**를 켭니다.
3. 처음 설치한다면 **압축해제된 확장 프로그램을 로드합니다**를 눌러 이 폴더를 선택합니다.
4. 기존 설치를 업데이트한다면 확장 카드의 **새로고침**을 누릅니다.
5. 로그인된 메이플스토리 웹 경매장 탭도 새로고침합니다.

`manifest.json`과 함께 `tools/`, `schemas/`가 포함된 폴더 전체를 로드해야 합니다. 파일 저장에는 File System Access API를 지원하는 최신 데스크톱 Chrome이 필요합니다.

## 수집 사용법

1. `https://auction.maplestory.nexon.com` 탭을 활성화합니다.
2. 확장 아이콘에서 **시세 수집 관리자 열기**를 누릅니다.
3. **market-data 폴더 선택**을 눌러 저장 루트에 읽기·쓰기 권한을 부여합니다.
4. 카탈로그 151종, P1/P2 수량, 검색 작업 진행도(`완료 수 / 185개`), 오늘의 일반·예비 사용량을 확인합니다. **조사 범위 보기**를 펼치면 완료된 장비와 미완료된 장비, 장비별 남은 검색 수를 확인할 수 있습니다. 전역 검색 35개는 장비별 목록의 분모에서는 제외하고 전체 검색 작업 진행도에만 포함합니다.
5. **수집 시작**을 누릅니다. 기존 체크포인트가 있으면 완료되지 않은 검색 작업부터 재개합니다. **현재 작업**에는 검색할 정확한 이름 또는 접두어와 `스타포스 제한 없음`, `스타포스 0성`, `스타포스 17성 이상` 같은 실제 제출 범위가 표시됩니다.
   - 다음 KST 날짜까지 보류된 오류 검색을 한번에 다시 넣으려면 시작 전 **실패한 작업 모두 포함**을 선택합니다. 이 선택은 해당 실행에만 적용되고, 0건 결과의 1·3·7·14일 재확인 대기는 우회하지 않습니다.
6. 멈추려면 **일시정지**를 누릅니다. 현재 검색의 남은 페이지를 처리한 뒤 멈추며, 다음 **수집 시작**에서 재개합니다.

구조화 응답 누락을 재현할 때는 **전체 네트워크 진단 → 네트워크 감시 시작**을 먼저 누른 뒤 수집을 실행합니다. 최대 5분 동안 연결된 경매장 탭과 `api.mskr.nexon.com`의 완료·오류·리다이렉트 요청을 브라우저 수준에서 기록하고, `/tool-tip` 요청과 페이지 구조화 응답 훅의 캡처 여부를 비교합니다. 진단 결과에는 응답 본문, 전체 URL, 계정·캐릭터 ID, 검색 키, 헤더가 들어가지 않습니다. 요청이 한 건도 보이지 않은 결과도 복사할 수 있습니다.

**수집 진행도 초기화**는 중단된 수신 원본을 먼저 복구한 뒤 모든 카탈로그 작업을 미완료로 되돌립니다. `raw/` 파일과 IndexedDB의 미저장 페이지, 누적 페이지·매물 수, 필터 검증 기록, 오늘의 사이트 검색 횟수는 유지합니다. 같은 날 다시 시작하면 남은 실제 검색 한도까지만 실행합니다.

수집 중에는 확장이 제어하는 경매장 탭의 검색어·필터·페이지를 수동으로 바꾸지 마세요. 정상 수집에서는 아이템에 마우스를 올리지 않으며 화면 툴팁도 띄우지 않습니다. 저장 폴더 권한이 만료되면 같은 `market-data` 폴더를 다시 선택하면 됩니다.

관리자 화면의 **검색 작업** 카드는 완료된 물리 검색 수를 `59 / 185개`처럼 표시합니다. 이 수치는 저장된 누적 원본 페이지 수나 오늘 사용한 검색 횟수와 다릅니다. 일부만 완료됐고 남은 작업이 모두 빈 결과 backoff 중이면 **재확인 대기**, 185개가 모두 완료됐을 때만 **전체 검색 완료**, 일반 한도 98회를 썼으면 **오늘 일반 조사 98회를 모두 사용했습니다**로 구분합니다.

**조사 범위 보기**의 장비 목록도 같은 물리 검색 기준을 사용합니다. 해당 장비의 검색 조건을 전부 완료하면 **완료된 장비**로 이동하며, 아직 남은 조건이나 빈 결과 재확인 대기가 하나라도 있으면 **미완료된 장비**에 남습니다.

### 검색 한도와 복구

- 날짜와 한도는 한국 표준시(KST, UTC+9) 자정에 바뀝니다. 일반 검색은 하루 98회, 예비 풀은 중단 복구용 2회이며 둘을 합쳐 100회를 넘지 않습니다.
- 일반 98회를 사용한 시점까지 복구 검색을 한 번도 쓰지 않았고 대기 중인 복구도 없으면, 남은 예비 2회를 미완료 일반 검색에 사용합니다. 복구를 1회라도 사용했다면 남은 예비는 일반 검색으로 전환하지 않습니다.
- 계정을 바꾸면 사이트 상단 횟수를 세 번 연속 확인한 뒤 한도와 레인 사용량만 새 계정 기준으로 잡습니다. 카탈로그 완료 기록·빈 결과 재확인일·복구 큐·누적 원본은 이어집니다. 계정명이나 캐릭터명은 한도 식별용으로 저장하지 않습니다.
- 검색은 요청 전에 먼저 예약합니다. 실제 요청 단계에 들어간 건은 결과가 없거나 창이 닫혀도 사용량으로 남습니다. 아직 요청하지 않은 `reserved` 건만 안전하게 반환할 수 있습니다.
- 응답까지 받은 미저장 페이지는 새 검색 없이 저장을 마칩니다. 요청 도중 중단되어 응답을 확인하지 못한 페이지는 재검색하므로 새 예비 한도가 필요할 수 있습니다.
- KST 날짜가 바뀌면 검색 카운터만 새로 시작합니다. 카탈로그 진행 지점과 저장 대기 페이지는 유지됩니다.
- 결과가 연속으로 비는 작업은 1일, 3일, 7일, 14일 간격으로 재시도해 한도를 낭비하지 않습니다.

일반 98회는 아래 레인별 **우선 목표**를 사용합니다. 먼저 목표가 남은 레인의 작업을 선택하고, 어떤 레인에 실행 가능한 작업이 부족해 목표를 채울 수 없으면 남은 일반 한도를 완료되지 않았고 빈 결과 재확인 대기 중도 아닌 다른 레인의 검색 작업에 재배분합니다. 따라서 실행 가능한 미완료 작업이 있는 동안 일반 사용량 98회를 채우며, 레인별 숫자는 하드 상한이 아닙니다.

| 주스탯 구간 | 28 |
| 올스탯 구간 | 2 |
| 드롭·메획 | 2 |
| 미트라 | 5 |
| 합계 | 98 |

레인 재배분은 일반 98회 안에서만 동작합니다. 99·100번째 검색은 위의 기존 규칙대로 복구 검색을 한 번도 쓰지 않았고 대기 중인 복구도 없을 때만 미완료 일반 검색에 사용할 수 있습니다.

### 60개씩 보기 고정

수집기는 먼저 세부 조건의 **필터 검색**을 실행해 새 결과가 생성됐는지 확인한 다음, 결과 화면 하단의 표시 개수 컨트롤을 읽습니다. 이미 60개이면 그대로 진행하고, 아니면 드롭다운에서 `60개씩 보기`를 직접 선택한 뒤 화면 반영을 다시 확인합니다. 첫 페이지 뒤에는 같은 페이지네이션 컨테이너에서 목표 페이지와 정확히 같은 숫자 버튼만 누릅니다. 현재 페이지나 목표 숫자 또는 상단의 `검색 횟수 n / 100`을 하나로 확인할 수 없으면 화살표·URL·직접 API 호출로 우회하지 않고 안전하게 중단합니다. 중간 페이지에서 중단된 작업은 저장 직전 페이지의 숫자를 직접 눌러 구조화 응답 서명을 확인하고, 같을 때만 저장된 목표 페이지 숫자를 눌러 재개합니다. 검색 결과가 바뀌었거나 목표 페이지가 사라졌거나 구버전 체크포인트라 서명이 없으면 과거 페이지에 이어 붙이지 않고 현재 검색의 1페이지부터 새 묶음으로 수집합니다.

### 페이지 저장과 재개

```text
market-data/
├─ raw/
│  └─ maple-auction_page_YYYYMMDD-HHmmss_<장비명>_p<페이지>_<ID8>.jsonl
├─ normalized/
│  └─ maple-auction_normalized_YYYYMMDD-HHmmss_<ID8>.jsonl
├─ training/
│  └─ auction-sold.csv
└─ manifests/
   └─ maple-auction_collector-state_<timestamp>_<ID8>.json
```

- `raw` 파일 한 개에는 한 페이지의 `maple-auction.capture.v2` 봉투(envelope)가 압축 JSON 한 줄로 저장됩니다.
- 저장할 페이지는 먼저 IndexedDB 대기열에 넣습니다. 파일 저장을 다시 실행해도 같은 내용이면 완료로 처리하고 덮어쓰지 않습니다. 같은 이름에 다른 내용이 있으면 `_recovered_...` 파일로 분리합니다.
- 기본 시세 검색, 0성·17성 이상 보강 검색과 전역 검색 35개는 각각 발급받은 같은 검색 키로 페이지를 순회해 최대 500건까지 저장합니다. 실제 결과 끝이나 500건 상한에 도달하면 해당 물리 검색을 완료합니다. 같은 페이지가 다시 수신되면 그 페이지는 저장하지 않고 복구 대상으로 남깁니다.
- 창세의 뱃지 최근 시세만 최신 첫 페이지 한 번 저장합니다. 데아 시두스 이어링·고귀한 이피아의 반지·카오스 혼테일의 목걸이·매커네이터 펜던트는 스타포스 1성 이상 단일 물리 검색으로 최대 500건을 수집합니다.
- 결과가 0건이면 1일·3일·7일·14일 간격의 빈 결과 규칙을 적용합니다. 검색 도중 실패한 페이지는 복구 예비 2회 범위에서 한 번 재시도하고, 다시 실패하면 다음 KST 날짜까지 보류합니다. **실패한 작업 모두 포함**을 켜면 보류 날짜 전에도 해당 검색을 이번 수집 대상으로 다시 넣습니다.
- **미저장 원본 확인**은 로컬 DB에 남은 페이지를 폴더로 다시 내보냅니다. **진행 상태 내보내기**는 원본 매물 대신 체크포인트 진단용 JSON을 `manifests/`에 저장합니다.
- **필터 입력 진단**은 `거대한 공포 · 스타포스 제한 없음 · 올스탯% 합산 15% 이상`을 실제 검색 1회로 점검합니다. 조건을 제출해 새 검색 결과를 확인한 뒤 그 결과를 `60개씩 보기`로 바꾸는 순서까지 진단합니다. 수집 진행도와 원본 파일은 바꾸지 않으며, 검색 횟수만 일일 한도에 반영합니다. 단계별 결과에서 **진단 결과 복사**를 누르면 검색 키 값·전체 URL·HTML·계정·월드·판매자 정보를 제외한 JSON만 복사됩니다.
- **전체 네트워크 진단**은 검색을 실행하지 않고 연결된 경매장 탭에서 완료·실패·리다이렉트된 비민감 네트워크 이벤트만 최대 400건 기록합니다. 경매장 API의 응답 본문을 읽는 기능이 아니라, 브라우저가 `/tool-tip` 응답을 받았는지와 페이지 훅이 같은 진단 구간에 구조화 응답을 잡았는지를 분리해 확인하는 도구입니다.
- 관리자를 다시 열 때 기존 관리자 창이 살아 있으면 그 창을 앞으로 가져옵니다. 창이 비정상 종료되어 실행 잠금만 남았다면 실제 창의 생존 여부를 확인해 자동으로 해제하며, 대기 중인 화면도 1.5초 간격으로 다시 확인합니다. 실행 잠금은 획득할 때마다 새 토큰을 발급하고 주기적으로 갱신합니다. 상태와 페이지 체크포인트는 그 토큰이 IndexedDB의 현재 잠금과 정확히 일치할 때만 저장하므로, 만료된 관리자 창이 새 수집 상태를 덮어쓸 수 없습니다.

브라우저 내부 복구 저장소는 IndexedDB `maple-auction-jsonl` 버전 2입니다. `collector_state`와 `page_captures`가 실제 복구 원본이며, `chrome.storage.local`의 `mapleAuctionCollectorCheckpointV1`은 작은 체크포인트 미러입니다.

## 검색 필터의 범위와 한계

자동 카탈로그 검색은 화면에서 판매완료·검색어·정확/부분검색 방식·최근 거래순·페이지 번호·페이지 크기와 적용된 필터를 다시 확인한 뒤 캡처합니다. 일치하지 않으면 해당 화면을 정상 결과로 확정하지 않습니다.

- 수집기는 최초 검색 URL에 장비명·범주·스타포스·잠재 조건을 넣지 않습니다. 단일 장비는 자동완성에서 정확한 이름을 선택하고, 묶음 장비는 검증된 세트 접두어로 부분검색을 제출합니다. 부분검색 결과는 쿼리의 `allowed_names`와 정확히 일치하는 행만 저장하고 이름으로 실제 `catalog_id`를 다시 결정합니다.
- 기본 검색은 스타포스 제한 없이 전체 구간을 확보하고, 별도의 0성 및 17성 이상 검색으로 양 끝 표본을 보강합니다. 세 검색 모두 결과 끝 또는 500건까지 숫자 페이지를 순회합니다. 창세의 뱃지만 최근 첫 페이지 한 번, 보조 보스 장신구 4종은 스타포스 1성 이상 단일 검색만 사용합니다.
- 고성 구간의 희소 표본은 장비명을 비운 전체 장비 공통 23성·24성·25성 이상 검색으로 추가 확보합니다. 스타포스가 가능한 고정 카탈로그 139종을 allowlist로 사용해 정확한 이름이 일치하는 결과만 저장·후분류하며, 세 검색 자체는 특정 장비의 완료 조건과 분리된 공통 고성 표본입니다.
- 드롭·메획은 장비명을 비우고 메소 획득량 증가 20% 이상과 아이템 획득 확률 증가 20% 이상을 각각 한 번 검색합니다. 두 검색의 모든 매물을 저장한 뒤 반지·펜던트·얼굴장식·눈장식·귀고리를 메획 40%, 드롭 40%, 메획 20%+드롭 20%, 메획 20%, 드롭 20%의 5개 목표로 로컬 후분류합니다. 고정 카탈로그에 없는 장신구도 이름과 옵션을 보존합니다.
- 서버의 스탯 잠재 필터는 엄격한 의미라고 가정하지 않습니다. 관측된 STR% 검색에는 올스탯% 결과가 포함될 수 있습니다. 올스탯은 `allStatsPercent`, 공격력%는 `physicalAttackPercent`가 현 사이트의 정상 필터 검색에서 확인됐으며 DEX/INT/LUK/마력 매핑은 계속 재검증합니다.
- HP%, 방무, 모자 쿨감, 장갑 크뎀은 확인되지 않은 URL 코드를 만들지 않고 기본 검색 결과의 툴팁에서 로컬 분류합니다. 아이템 획득 확률 증가·메소 획득량 증가는 전용 전역 검색 2개의 응답을 다시 판정합니다.
- 장신구는 STR·DEX·INT·LUK 27~29%/30~32%/33% 이상과 올스탯 21% 이상, 방어구는 네 주스탯 27~29%/30~32%/33~35%/36% 이상과 올스탯 21% 이상을 별도로 조사합니다. 경매장에는 각 구간의 최소값을 입력하고, 저장 전에 선택 스탯+올스탯 합계와 장비 분류를 다시 읽어 구간 상한 밖 결과를 제외합니다. 여러 검색에 같은 거래가 보이면 학습 자료 생성 시 거래 식별자로 한 건만 남깁니다.
- URL 조건이 같은 로컬 전용 프로필은 해당 물리 검색 페이지들을 함께 사용합니다. 하나의 물리 검색이 완료되면 형제 레인도 함께 완료하므로 동일 조건을 프로필마다 반복 검색하지 않습니다.
- 서버 검색에서 포함된 올스탯은 로컬에서 한 번만 합산합니다. 제논용 STR/DEX/LUK/올스탯은 각각 보존하며 하나의 수치로 접지 않습니다. HP는 올스탯과 합치지 않습니다.
- 드롭·메소 프로필은 전용 검색 2개의 결과 중 반지·펜던트·얼굴장식·눈장식·귀고리에만 적용합니다. 어깨장식은 방어구이므로 이 채널에 넣지 않습니다.
- 쿨감은 모자, 크뎀은 장갑에만 적용합니다. 미트라는 스타포스·보공 전용 검색을 만들지 않으며, 마법사는 마력, 나머지 네 직업군은 공격력 기준으로 분류합니다.
- `스킬 재사용 대기시간 -1초/-2초`와 `캐릭터 기준 9레벨 당 STR/DEX/INT/LUK +1/+2`는 원문과 수치를 구조화해 저장합니다. 쓸만한 스킬처럼 시장 가치에서 제외할 옵션도 원문은 보존합니다.
- 특수 프로필이 적용되지 않는 매물도 기본 시세 표본에서는 버리지 않습니다. “전용 채널을 생성하지 않음”과 “가격 표본에서 제외”는 다릅니다.

스타포스는 목록 배지와 판매 툴팁의 별 SVG를 함께 확인합니다. 활성 별이 하나도 없고 비활성 별 영역이 확인되면 `0성`으로 저장합니다. 별 영역이 노출되지 않더라도 검증된 정확 범위 필터(`0~0성`, `23~23성`, `24~24성`)이면 검색조건 추론값을 남깁니다. `25성 이상`처럼 범위가 열린 필터는 정확한 수치를 추론하지 않습니다. 스타포스 강화 불가 장비는 `비적용`, 근거가 부족한 장비만 `unknown`으로 구분합니다.

잠재의 로컬 분류 경계는 장비 기본 레벨 201에서 바뀝니다.

| 기본 레벨 | 주스탯·HP 2줄 / 3줄 | 올스탯 2줄 / 3줄 |
|---|---|---|
| 0~200 | 21% / 30% | 15% / 21% |
| 201 이상 | 23% / 33% | 17% / 24% |

미트라 정옵은 해당 공/마 30% 또는 공/마 21% + 방무 30%입니다. 공/마 18% + 방무 35% 매물은 기본 가격 표본으로 남길 수 있지만 정옵으로 분류하지 않습니다.

## 정규화와 학습 CSV

Node.js 20 이상에서 실행합니다.

```powershell
node tools/normalize.mjs "경로\raw\maple-auction_page_....jsonl"
node tools/build-training.mjs "경로\normalized\maple-auction_normalized_....jsonl"
```

출력 경로를 직접 지정하려면 각 명령의 마지막 인수로 파일 경로를 추가합니다. 정규화기는 원본을 읽기 전용으로 다시 확인하고 새 파일을 만들며, 기존 `maple-auction.raw.v1` JSONL과 v0.5의 `capture.v2` JSON도 계속 읽습니다.

학습 CSV 생성 규칙은 다음과 같습니다.

- `listing.status === "sold"`인 행만 출력합니다.
- 경매장이 제공한 네이티브 `listing_id`가 같은 행은 하나로 합치고, 일치 쿼리·선택 채널 목록을 병합합니다.
- 네이티브 ID가 없으면 지문을 전역 거래 ID로 취급하지 않습니다. 다만 서로 다른 수집 시도에서 장비·지문·거래일·가격·월드가 모두 같은 fallback 관측은 중복 수집으로 보고 합칩니다. 한 결과 페이지에 실제로 같은 매물이 여러 개 있던 경우를 지우지 않도록, 시도별 중복 개수 중 가장 큰 개수는 그대로 보존합니다.
- 비교 캐릭터 의존 값, 가격 원문, CSS/RGB, 원문 툴팁, 복구·품질·디버그 정보와 개인정보 관련 필드는 CSV에서 제외합니다.

## 개인정보와 보안

판매자·제작자 닉네임, 쿠키, Authorization/CSRF/OTP 토큰, 세션·계정 정보, 브라우저 저장소 전체, 전체 HTML은 수집하지 않습니다. 구조화 응답에 포함된 매물·아이템 식별자는 SHA-256으로 바꿔 저장하고, 계정 ID·캐릭터 ID·검색 키·원본 요청 URL은 브리지 단계에서 제거합니다. `raw/`에는 아이템과 검색 근거가 포함되므로 공유 전에도 내용을 확인하세요.
