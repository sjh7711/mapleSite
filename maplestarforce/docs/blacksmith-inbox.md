# 대장장이 신청함

운영·프리뷰 모두 `VITE_STARFORCE_INBOX_ENABLED=true`로 신청함을 제공한다. 신청 API는 각 환경 전용 VM SQLite에 연결한다. Pages의 기존 D1 바인딩은 롤백용으로 보존하며, 관리자 로그인과 가격 설정은 기존 구조를 유지한다. 운영 구성과 복구 절차는 `services/blacksmith-inbox/README.md`를 따른다. 운영과 프리뷰의 신청함·차단 정보·접수 주소는 서로 분리한다. 기존 프리뷰 신청함은 프리뷰에서 계속 관리한다.

## 사용 흐름

1. 진행자가 상단의 **대장장이 예약**을 누르면 같은 창의 본문에 생성 폼을 바로 표시한다. 이름을 입력하고 봇 확인 후 생성한다. 안내문은 진행자만 생성하도록 요청하고, 12시간 동안 새 요청이 없으면 자동 폐기된다는 두 줄을 16px로 표시한다. 생성 후 상단에는 이름을 표시하고 생성 폼을 신청 목록으로 바꾼다. 기존 신청함을 폐기하거나 만료된 뒤 다시 생성할 수 있다. 이전에 만든 신청함이 여러 개라면 모두 보존하고 선택할 수 있지만 새 신청함은 추가하지 않는다.
2. 생성한 브라우저에 관리 권한을 자동 저장하고 다음 방문부터 자동 연결한다. 저장된 관리 권한이 없는 브라우저도 생성 당시와 같은 IP이면 기존 대장장이 관리로 승인 없이 연결한다. 시크릿 탭과 같은 공유기를 사용하는 다른 기기에도 적용하며 신청 조회·처리·종료를 허용한다. **접수 주소**만 신청자에게 공유한다. 관리 코드 입력·복사와 접수 코드는 지원하지 않는다. 원래 브라우저에 저장된 관리 권한은 IP가 바뀌어도 유지하며, IP로 연결한 브라우저는 매 요청마다 생성 IP가 일치해야 한다. 사이트 저장 데이터를 삭제해도 같은 생성 IP에서는 다시 연결할 수 있다.
3. 신청자는 접수 주소에서 장비와 시작·목표 성수를 선택하고 **신청**한다. 상단에는 **이름 대장장이 신청서**를 표시하며 신청 팝업은 최대 440px 폭으로 연다. 이름, 장비, 성수, 수량, 일반/장갑·무기 선택만 전송한다. 가격·이벤트·MVP·PC방·대장장이 배율은 전송하지 않는다.
4. 진행자의 열린 계산기는 5초마다 새 신청을 확인한다. 숨긴 탭은 확인을 멈추고, 연결 실패 시 최대 60초 간격으로 재시도한다. 신청 도착은 현재 계산을 바꾸지 않는다.
5. **장비 불러오기**를 누른 신청은 별도 작업 공간에서 연다. 진행자의 가격과 공통 조건을 적용한다. 작업 수정값은 신청별로 이 브라우저에 보관하며 **내 슬롯으로 돌아가기**로 원래 세 슬롯에 복귀한다. 작업 바의 **완료**는 서버에 완료 상태를 저장한 뒤 원래 슬롯으로 복귀한다. 저장에 실패하면 작업과 수정값을 유지하고 작업 바에 오류를 표시한다. 새로고침도 원래 슬롯을 연다.
6. **대장장이 종료**를 확인하면 신청함과 모든 신청을 삭제한다. 이 브라우저의 해당 작업 수정값도 삭제하고 원래 세 슬롯으로 복귀한다.

## 신청 화면과 목록

빈 신청 목록은 안내 텍스트 없이 최소 400px 높이의 공간을 확보한다. 접수 주소 복사 성공은 버튼 왼쪽 위의 **복사완료** 오버레이로 잠시 표시한다. 개별 신청 삭제 버튼의 이름은 **거절**이며 확인 후 해당 신청을 제거한다.

신청 시각은 닉네임 바로 뒤에 띄어쓰기 한 칸을 두고 표시한다. 그 아래에는 **장비 N개, 기댓값 xxx.xx억메소**를 표시한다. 금액은 진행자의 현재 이벤트·MVP·PC방·스페어값·대장장이 배율로 계산하여 해당 신청을 불러왔을 때의 **준비할 메소**와 일치시킨다. 작업 중이거나 저장된 신청 수정값이 있으면 그 장비·가격·전략을 적용한다. 계산 설정과 가격이 바뀌면 표시 금액도 갱신한다. 계산 실패 시 부분 합계 대신 계산 불가를 표시한다.

목록 바깥 바로 위 왼쪽에 **대기중·N/50 / 진행중·N/50 / 완료·N/300** 필터를 둔다. 건수는 검색·상태 선택·완료 페이지와 관계없이 해당 신청함의 전체 상태별 건수이며, 대기·진행은 50건의 접수 정원을 공유한다. 기본은 전체 표시이며 버튼을 누르면 해당 상태만 표시한다. 선택한 버튼을 다시 누르면 전체로 돌아온다. 선택은 신청함을 닫고 열어도 유지하며 신청함을 바꾸면 전체로 초기화한다.

대기중·진행중 신청의 **장비 보기**를 펼치면 접수한 장비와 시작·목표 성수를 확인할 수 있다. 슬롯이나 처리 상태는 바뀌지 않는다. 신청자도 자기 접수 화면의 **신청 장비 보기**로 같은 목록을 확인할 수 있다.

완료 내역은 최근 접수 300건을 보관하고 20건씩 페이지를 나눠 표시한다. 새 완료 처리로 300건을 넘으면 접수 시각이 가장 오래된 완료 건을 삭제한다. 대기중·진행중은 합계 최대 50건을 별도로 허용하며 완료 건은 접수 정원을 차지하지 않는다. 마이그레이션은 기존 완료 내역도 최근 300건으로 정리한다. 이전에 이미 50건을 넘게 접수한 신청함의 미완료 신청은 삭제하지 않고 보존하며, 50건 미만이 되어야 새 접수·완료 건 재대기를 허용한다. D1 트리거에서도 정원을 검사하므로 이전 배포 주소의 코드로 제한을 우회할 수 없다.

같은 줄 오른쪽의 **닉네임·초성 검색**은 이름 일부나 초성으로 검색하며 상태 필터와 함께 적용한다. `신청자`는 `ㅅㅊㅈ`, `ㅊㅈ`, `신ㅊ자`로도 찾을 수 있다. 영문 대소문자와 한글 정규화 차이를 무시한다. 검색어는 신청함을 닫고 열어도 유지하고 다른 신청함을 선택하면 초기화한다. 검색 결과가 없어도 빈 목록 영역은 유지한다.

대기중과 진행중은 같은 정렬 우선순위로 접수 시각이 오래된 신청부터 표시한다. 진행중으로 전환해도 대기열 내 위치는 유지한다. 완료된 신청은 미완료 신청보다 아래로 이동하며, 완료 내역끼리는 접수 시각이 최근인 신청을 위에 표시한다. 정렬·필터는 서버 데이터를 변경하지 않는다.

## 신청자 수정·철회 및 추가 신청 제한

- 같은 신청함에 대기중·진행중 접수가 있으면 추가 신청을 받지 않는다. 같은 IP, 같은 신청 브라우저, 같은 닉네임 중 하나가 기존 미완료 접수와 일치하면 서버에서 차단한다. 완료·거절·철회 이후에는 신청 횟수 한도 안에서 다시 신청할 수 있다.
- 같은 신청함에서 처음 사용한 닉네임은 해당 신청 브라우저에 연결한다. 영문 대소문자를 구분하지 않으며 다른 브라우저가 같은 이름으로 신청하거나 수정할 수 없다. 완료·이름 변경 후에도 연결은 유지하며, 신청자가 대기 접수를 철회하거나 진행자가 거절하면 그 접수가 예약한 이름을 해제한다. 신청함 폐기 시 예약도 함께 삭제한다. 본인 브라우저는 완료·거절·철회 후 그 이름으로 다시 신청할 수 있다. 게임 계정 본인 인증을 의미하지 않으며 사이트 저장 데이터를 지우면 기존 이름의 권한을 복구할 수 없다.
- 같은 IP에서는 신청함 전체를 통틀어 최근 30분 동안 정상 접수한 신청이 최대 3건이다. 고정된 30분 구간이 아니라 각 요청 시각 직전 30분을 계산한다. 철회·거절·신청함 폐기로 횟수를 돌려주지 않으며, 같은 접수 번호의 정상 재시도는 횟수에 중복 반영하지 않는다.
- 신청 브라우저에 별도의 무작위 256비트 내부 인증값을 자동 저장한다. 이 값은 코드로 표시하지 않고 요청 헤더에만 사용한다. 서버는 신청함별 해시만 보관하며 IP 자체는 철회·수정 권한을 부여하지 않는다. 같은 IP의 다른 브라우저는 접수 존재 여부만 확인하고 장비나 닉네임을 조회·변경하지 못한다.
- 대기중일 때 **신청 수정**을 누르면 서버의 기존 장비를 별도 계산 공간에서 연다. 수정 후 **수정 저장**과 봇 확인으로 같은 접수 내용을 갱신한다. **수정 취소**는 원래 슬롯으로 돌아온다. 신청 ID·접수 시각·접수순번은 유지하며 수정은 새 신청 횟수나 신청함 12시간 유효기간을 갱신하지 않는다.
- 신청 수정은 접수 건당 성공한 저장을 최대 5회까지 허용한다. 기존 수정 버전도 횟수에 포함하며 남은 횟수를 신청 화면에 표시한다. 취소·실패·같은 내용 재전송은 차감하지 않는다. 서버의 수정 버전을 원자적으로 증가시켜 새로고침·다른 탭·직접 API 요청으로 한도를 넘지 못하게 한다. 5회 소진 후에도 대기 신청 철회는 가능하다.
- 대기중일 때 **신청 철회**를 확인하면 본인 접수와 그 접수에서 예약한 수정 전후 닉네임을 한 트랜잭션으로 삭제한다. 접수 중지 상태에서도 철회할 수 있다. 진행중 신청은 수정·철회를 허용하지 않으며, 철회 실패 시 예약도 유지한다.
- 수정 버전을 검증하여 서로 다른 탭의 덮어쓰기를 막는다. 진행자는 최신 장비를 확인한 뒤 같은 버전을 진행중으로 확정해야 작업 공간이 열린다. 수정·철회와 진행 시작이 겹치면 서버에서 한 동작만 성공한다. 새 버전의 신청에는 과거 버전의 진행자 작업 수정값을 적용하지 않는다.
- 변경 전 접수는 신청자 인증정보와 IP 해시가 없으므로 본인 수정·철회를 연결하지 않는다. 기존 내역과 진행자 관리 권한은 유지하며 진행자가 거절할 수 있다. 기존 접수의 이름은 소유자를 알 수 없는 예약 이름으로 이전하여 다른 사람이 사용하지 못하게 한다.

## 12시간 자동 폐기

- 생성 시 12시간의 유효기간을 설정한다. 새로운 신청이 정상 접수될 때마다 그 시각부터 12시간으로 연장한다.
- 조회·자동 폴링·접수 중지/재개·처리 상태 변경·개별 신청 삭제·같은 신청 번호 재전송은 유효기간을 연장하지 않는다.
- 기한이 지나면 API가 즉시 접근과 신규 신청을 막고 해당 신청함과 모든 신청을 삭제한다. 새 신청과 만료 조회가 동시에 발생해도 SQL에서 현재 기한을 다시 확인하여 정상 갱신된 신청함을 삭제하지 않는다.
- 각 환경의 VM 서비스가 5분마다 만료 신청함을 정리한다. 운영의 기존 D1 정리 스케줄은 중지했다. 열린 브라우저가 없어도 동작하며 한 번에 최대 100개 신청함을 정리한다. 기한 이후 실제 DB 정리는 다음 예약 작업에서 이루어질 수 있지만 API 접근은 즉시 차단된다.
- 기존 신청함은 생성 시각과 마지막 신청 접수 시각 중 늦은 시각을 기준으로 이전한다. 기존 브라우저에 저장된 권한은 자동 이전한다. 만료된 신청함은 조회 시 브라우저 목록과 해당 작업 수정값에서도 제거한다.

## 방어 및 접근 제어

- 생성 브라우저에 무작위 256비트 내부 인증값을 자동 보관한다. 서버에는 SHA-256 해시만 저장하며, 신청 목록·장비 상세·처리 상태·대장장이 종료는 기존 인증값 또는 생성 IP 일치 여부를 매번 검증한다. `GET /api/blacksmith-inboxes/managed`는 생성 IP와 일치하는 미만료 대장장이 정보만 반환하며 원본 IP·IP 해시·관리 인증값을 반환하지 않는다. 시크릿 탭의 IP 연결에는 영구 관리 인증값을 발급하지 않는다. 같은 공인 IP를 공유하는 사람도 승인 없이 관리할 수 있는 정책이다. 접수 중지 상태도 연결하며 종료·만료된 대장장이는 제외한다. 기존 IP 기록이 없는 예약은 원래 브라우저 인증값으로만 관리한다. 신청자의 본인 조회·수정·철회와 사이트 관리자 인증은 별개로 유지한다.
- Turnstile managed 확인은 신청함 생성과 신청 제출에서만 수행한다. 서버는 `success`, 정확한 action(`inbox_create`/`inbox_submit`), 현재 배포 호스트를 확인하며 실패 시 저장하지 않는다. 토큰은 매 제출 시 갱신한다.
- IP별 신청함 생성 1시간 5회, 전체 신청함 제출은 최근 30분 3회. IP는 해시만 보관한다. 접수 저장과 횟수 반영을 SQLite batch 트랜잭션에서 처리하고 부분 고유 인덱스로 미완료 접수의 중복을 방지한다. 재전송 ID는 같은 신청자·내용에 한해 멱등 처리하며 철회한 ID를 재사용하여 횟수를 우회할 수 없다.
- 신청함당 미완료 합계 최대 50건·완료 보관 최대 300건, 신청당 장비 최대 100개, JSON 최대 48KB. 장비 종류·레벨·성수·수량은 서버에서 허용 목록으로 검증한다. 신청 텍스트를 HTML로 삽입하지 않는다.
- 진행자는 접수를 중지·재개하고 개별 신청 삭제 또는 신청함 전체 폐기를 할 수 있다. 신청함 폐기 시 외래 키의 `ON DELETE CASCADE`로 모든 신청 내용도 제거한다.
- 이 제한은 도배 피해를 줄이는 방어이며 사람의 악의적 신청이나 분산 공격을 완전히 방지한다는 보장은 아니다. 계정 전체 Workers/D1 무료 한도는 기존 서비스와 공유한다.

## 인프라

- Pages: 기존 `starforce` 프로젝트의 production(main)·preview 환경을 사용한다.
- D1: 프리뷰 `starforce-inbox-preview`, 운영 `starforce-inbox-production`을 각 환경의 `STARFORCE_INBOX_DB`로 연결한다. 기존 가격 설정 DB와 분리한다. 마이그레이션은 `migrations/blacksmith-inbox`에 있다.
- 예약 정리: 프리뷰 `workers/inbox-cleanup/wrangler.jsonc`, 운영 `workers/inbox-cleanup/wrangler.production.jsonc`. 각 환경의 신청 DB만 바인딩하고 HTTP 경로와 workers.dev 공개 주소를 만들지 않는다. 요청 제한 namespace도 환경별로 분리한다. `*/5 * * * *` Cron Trigger를 등록한다.
- 비밀키: Pages production·preview의 암호화된 `TURNSTILE_SECRET`. 공개 sitekey는 각 환경 vars의 `TURNSTILE_SITEKEY`이다. 비밀키를 파일·소스·응답에 출력하지 않는다.
- Turnstile 허용 도메인: `starforce.pages.dev`, `preview.starforce.pages.dev`, `localhost`, `127.0.0.1`. 백엔드는 반드시 요청 배포의 정확한 호스트와 검증 결과를 비교한다.
- 정상 폴링은 인덱스가 있는 신청함 한 행만 읽는다. revision이나 검색·완료 페이지가 바뀌면 보관된 요약 전체(새 신청함은 최대 350건, 이전 정원 초과 미완료는 별도 보존)에서 검색하고, 검색에 맞는 미완료와 완료 20건만 장비와 함께 반환한다. 기존 신청함의 생성자 식별 등록 1회를 제외한 폴링은 DB에 쓰지 않는다.
- 관리자가 `includeItems=1`로 목록을 조회하면 검증된 신청 장비를 함께 받아 브라우저에서 기댓값을 계산한다. 장비는 공개 조회에 포함하지 않으며, revision이 같은 폴링에는 재전송하지 않는다. 신청별 상세 조회를 추가로 반복하지 않는다.
- 신청자는 본인의 미완료 접수가 있는 동안에만 10초마다 상태를 확인하며 숨긴 탭은 멈춘다. 신청 내용이 없는 페이지는 초기 진입·포커스·신청 동작에서 상태를 확인한다. IP별 횟수 기록은 접수 삭제와 독립적으로 보관하고, VM 정리 작업이 30분이 지난 기록을 한 번에 최대 200건 삭제한다.

## 검증

`node --test test/blacksmith-inbox.test.mjs`는 Miniflare D1과 명시적인 Siteverify 응답 대역을 사용한다. 인증 격리, 봇 확인 실패·재사용·다른 action/host, 요청 크기, 접수 코드 제거·접수중지, 중복·동시 접수, 제출 제한·최대 건수, 전체 폐기·외래 키 삭제, 유효기간 연장 조건, 예약 정리, 기존 데이터 이전, 슬롯 및 작업 수정값 보존을 검증한다. 대역을 쓰는 이 테스트만으로 실제 Turnstile의 브라우저 동작이 검증된 것은 아니다.

함수 타입은 `wrangler types functions/starforce-admin-env.d.ts --include-runtime=false --strict-vars=false --env-file /tmp/starforce-inbox-type-env.env`로 생성했다. 이 임시 파일은 실제 비밀값 없이 `STARFORCE_ADMIN_PASSWORD_HASH`와 `TURNSTILE_SECRET`의 문자열 타입만 선언한다.

예약·보호 Worker 타입은 `wrangler types workers/inbox-cleanup/worker-configuration.d.ts --config workers/inbox-cleanup/wrangler.jsonc --include-runtime=false`로 생성한다. 배포 시 `wrangler d1 migrations apply STARFORCE_INBOX_DB --env preview --remote`로 신청 DB만 이전하고 `wrangler deploy --config workers/inbox-cleanup/wrangler.jsonc`로 정리 Worker를 배포한 뒤 Pages의 preview 브랜치에 빌드를 배포한다. 운영은 `wrangler d1 migrations apply STARFORCE_INBOX_DB --remote`, `wrangler deploy --config workers/inbox-cleanup/wrangler.production.jsonc` 후 production 빌드를 main 브랜치로 배포한다. 가격 DB는 변경하지 않는다.

## 서버 보호 정책 (2026-11-03)

### 사이트 관리자 관리 화면

- `/admin/starforce-prices/`의 **대장장이 관리** 메뉴에서 `/admin/blacksmith-inboxes/`로 이동한다. 운영·프리뷰에서 메뉴를 표시하며 기존 관리자 비밀번호·보안 쿠키·4시간 세션을 그대로 사용한다. HTML은 빌드 후 공개 정적 자산에서 제거하여 Functions에서 인증 후 제공한다.
- `/api/admin/blacksmith-inboxes`는 사이트 관리자 인증을 매번 확인한다. 신청함 진행자의 관리 인증값이나 신청자 인증값으로 접근할 수 없다. 미로그인은 로그인 화면으로 안내하고 API는 401을 반환한다.
- 전체 활성 정원, 접수 중·중지·만료 수를 표시한다. 전체 신청함을 이름 검색·상태 필터·생성 역순으로 20개씩 조회하며, 각 행에 대기·진행·완료 건수와 생성·폐기 예정 시각을 표시한다. 조회는 수동 새로고침과 검색 시에만 수행한다.
- 접수 중지·재개와 신청함별 폐기를 제공한다. 폐기 전 이름과 삭제할 접수 건수를 확인한다. 목록을 본 이후 접수 내용이나 진행자 설정이 바뀌면 버전 검사로 변경·폐기를 거부하고 다시 확인하게 한다. 만료된 신청함은 재개하지 못한다.
- 폐기는 신청함과 접수·닉네임 예약을 함께 삭제하고 정원을 반환한다. IP별 최근 30분 신청 횟수는 환불하지 않는다. 실제 신청함은 기능 검증 중 임의로 변경하거나 폐기하지 않는다.
- 관리자 요약 API는 진행자·신청자 인증 해시, IP, 신청자 이름이나 장비를 반환하지 않는다. 변경 요청에는 정확한 Origin, JSON 크기·스키마·버전을 검증하고 응답과 관리 HTML은 캐시하지 않는다. 비활성 환경에서는 관리 API·페이지를 제공하지 않는다.
- 검증은 `test/blacksmith-inbox-admin.test.mjs`를 포함한다.

### 관리자 활동 시각·생성 IP 차단

- 신청함 관리 목록은 생성·폐기 예정 시각을 한 줄에, 최근 신청·최근 완료 시각을 다음 줄에 표시한다. 최근 생성·신청·완료 역순 정렬을 서버에서 페이지 나누기 전에 적용한다. 검색·접수 상태 필터와 함께 사용할 수 있다. 기록이 없는 시각은 `—`로 표시한다.
- 최근 신청은 마지막으로 성공한 새 접수의 시각이다. 수정·철회·거절·완료로 초기화하지 않는다. 최근 완료는 대기/진행에서 완료로 변경한 실제 시각이며, 이미 완료된 건에 같은 상태를 재요청해도 갱신하지 않는다. 이전 버전의 완료 시각은 기록되지 않았으므로 임의로 접수일을 대입하지 않는다.
- 진행자의 신청함 창은 이름 오른쪽에 한국 시간 기준 자동 폐기 예정 시각을 표시한다. 새 접수로 만료 기한이 연장되면 기존 폴링으로 갱신한다.
- 신청서의 접수 중지 안내는 `지금은 접수를 받지 않는 상태입니다.`, 폐기·만료·없는 신청함 안내는 `이미 종료된 대장장이입니다.`로 구분한다. 종료된 링크는 신청 안내·신청 동작·중복 오류 메시지를 숨기고, 접수 중지는 기존 신청의 장비 조회와 철회 기능을 유지한다.
- 배포 후 생성되는 신청함에는 Cloudflare가 제공한 `CF-Connecting-IP`를 해시한 생성 식별값만 저장한다. 이전 신청함의 생성 IP는 복원할 수 없으며 차단 버튼을 비활성화한다. 원문 IP나 해시는 공개/관리자 응답에 포함하지 않는다.
- 사이트 관리자는 각 신청함의 `생성 IP 차단`으로 해당 IP에서 새 신청함을 만들지 못하게 한다. 기존 신청함의 접수·관리 기능은 변경하지 않는다. 같은 네트워크의 다른 사용자도 같은 IP를 사용하면 영향을 받을 수 있으므로 확인 창에서 알린다. 브라우저 식별값을 바꿔도 차단은 적용되며 생성 INSERT 안에서도 차단을 다시 검사한다.
- 차단은 별도 테이블로 유지하므로 원래 신청함의 폐기·자동 만료로 해제되지 않는다. 관리자 화면의 `차단한 생성 IP 관리`에서 20개씩 조회하고 해제할 수 있다. 생성 IP를 외부 입력으로 지정하거나 변경할 수 없으며 관리자 인증·Origin·JSON 검증을 모든 차단 변경에 적용한다.

### 공통 제한

- 생성 권한은 공개 상태이며 별도의 대장장이 신원 확인·승인 절차는 없다. 브라우저당 활성 신청함은 서버 고유 인덱스와 원자적 생성으로 1개만 허용한다. IP당 생성 시도 1시간 5회, 서비스 전체 활성 신청함 100개도 서버에서 검사한다. 만료·폐기 후 다시 만들 수 있다. 브라우저 식별값을 바꾸는 것은 새 사람임을 증명하지 않으므로 IP·봇 확인·전체 상한을 함께 둔다.
- 활성 신청함의 대장장이 이름은 중복 생성하지 못한다. 이름의 양끝 공백을 제거하고 NFC로 정규화하며 ASCII 영문 대소문자는 구분하지 않는다. 생성 트랜잭션 안에서 이름을 검사하여 동시 생성도 차단한다. 폐기·만료 후에는 다른 브라우저에서도 이름을 재사용할 수 있지만 이전 관리 권한을 승계하지 않는다. 기존 중복 이름 신청함은 삭제하거나 강제 변경하지 않으며 새 중복 생성만 막는다.
- 거절·철회 시 해당 접수 건의 닉네임 예약을 해제하고 완료는 예약을 유지한다. 같은 브라우저가 이름을 새 접수에 다시 사용한 경우 이전 건을 거절해도 새 접수의 예약은 해제하지 않는다. 제출 횟수는 거절·철회로 환불하지 않는다. 이번 변경 이전에 이미 삭제된 접수의 예약은 완료 내역 정리로 남은 예약과 구별할 수 없어 일괄 해제하지 않는다.
- 각 환경의 Pages는 D1 접근 전에 `INBOX_TRAFFIC` 서비스 바인딩으로 보호 Worker를 호출한다. 성공·인증 실패·없는 주소·잘못된 본문·config 조회 모두 같은 속도 제한을 거친다. 보호 서비스 오류 시 503으로 저장을 차단한다.
- 브라우저 기준 조회 분당 60회·변경 시도 분당 20회, IP 보조 제한은 조회 분당 300회·변경 시도 분당 120회다. 내부 Worker의 Rate Limiting 바인딩을 사용하므로 차단된 요청은 D1을 사용하지 않는다. 내부 Worker는 공개 HTTP 경로 없이 서비스 바인딩으로만 접근한다. 식별값은 해시로 전달한다.
- 이 속도 제한은 Cloudflare 위치별 근사 제한이다. 엄격한 전역 접수 횟수·정원·생성 수는 D1 트랜잭션으로 별도 검사한다. 제한된 요청도 Pages/Workers 실행 횟수에 포함되므로 대규모 분산 공격으로부터 계정의 무료 요청 한도를 완전히 보호하지는 않는다.

검증에 `test/blacksmith-inbox-traffic.test.mjs`를 포함한다. 현재 로컬 workerd가 지원하는 2026-08-29 호환 날짜로 실제 Rate Limiting API를 검증하고, 배포 Worker는 기존 2026-11-02 호환 날짜를 유지한다.

상단 신청함 버튼에는 기존 복사·붙여넣기 버튼과 같은 SVG 아이콘 형식의 망치를 사용한다. 세 버튼을 같은 묶음에 넣어 망치는 붙여넣기 바로 오른쪽에 유지한다. 760px 이하 화면에서는 텍스트를 숨기고 아이콘만 표시하며, 접근성 이름과 툴팁에는 대기 건수를 유지한다.

신청 목록은 비어 있어도 최소 높이 400px을 확보한다(기존 160px의 2.5배). 화면 높이를 넘는 경우 기존 신청함 대화상자 안에서 스크롤한다.

운영 반영 시 관리자 신청함 관리의 설명 두 문구와 스페어값 관리의 공통 가격 적용 설명 문구는 제거했다.

예약을 열기 전에는 목록·상태 필터·검색을 만들지 않고, 같은 창 본문에 안내·이름 입력·봇 확인·예약 열기 버튼을 포함한 생성 폼을 표시한다. 추가 생성 팝업은 띄우지 않는다. 생성·저장된 신청함이 있으면 이름·폐기 시각·접수 주소·목록으로 바뀌며, 폐기·만료 후에는 생성 폼으로 돌아간다. 폼을 닫거나 목록으로 전환하면 봇 확인 위젯을 정리한다.

상단 버튼은 신청함이 없으면 `대장장이 예약 열기`, 이미 만든 신청함이 있으면 `대장장이 대기열 · 대기 N`으로 표시한다. 아이콘 전용 화면에서도 접근성 이름과 툴팁은 같은 상태를 반영한다.

관리자 화면은 제목·메뉴·상태·오류·확인·완료 메시지에 `대장장이`와 `종료` 용어를 사용한다. 활성 대장장이, 접수 일시 중지, 자동 종료/자동 종료 예정으로 표시하며, 종료 성공 메시지는 `대장장이를 종료했습니다.`이다. API 주소·필드·DB·접수/정리 동작은 유지한다.


### 관리자 종료 이력 (3일 보관)

- 현재 대장장이의 `신청 내역 보기`에서도 신청자별 장비·처리 상태·접수 시각·수정 횟수를 20건씩 확인한다. 대기·진행은 함께 접수순, 완료는 그 아래에 최신 접수순으로 표시한다. 펼칠 때와 상세 새로고침 때만 조회하며 진행자의 작업·예약 기한·처리 상태를 변경하지 않는다. 상세 API는 사이트 관리자 세션과 기존 비공개 VM 연결로만 접근하고 인증정보·IP 해시는 반환하지 않는다. 버튼 이름은 `IP 차단`을 사용한다.
- 상세 새로고침은 펼치기 제목과 같은 줄에 배치한다. 현재 대장장이의 각 신청자 옆 `차단`은 진행자용과 동일하게 신청을 거절하고 닉네임 예약을 제거하며, 이번 대장장이가 종료될 때까지 저장된 신청자 식별값·IP의 재신청을 막는다. 신청자와 장비는 별도 차단 저장소에 남기고 화면에서는 완료 신청 아래에 `차단됨`과 `차단 해제` 버튼으로 표시한다. 새 탭·별도 구역은 만들지 않고 기존 상태 필터에서도 차단 기록을 아래에 유지한다. 차단 기록은 대기·진행 50건, 완료 300건 정원에 포함하지 않으며 완료·차단 내역의 페이지당 20건 조회는 함께 적용한다. 차단 해제는 기록과 제한을 제거할 뿐 신청을 복원하거나 제출 횟수를 환불하지 않는다. 관리자 세션·Origin·수정 버전 또는 차단 시각을 검증한다. 과거 차단에서 이미 삭제한 장비·닉네임은 복구할 수 없어 `이전 차단 신청`으로 표시한다. 종료 이력은 조회만 제공하며 차단 기록도 3일 보관한다.

- 관리자 대장장이 관리에서 `현재 대장장이`와 `종료 이력`을 전환한다. 종료 이력은 최근 종료·최근 생성·최근 완료 순 정렬, 이름 검색, 종료 구분 필터와 20개 단위 페이지를 제공한다.
- 직접 종료, 관리자 종료, 12시간 자동 종료를 구분하여 생성·종료·최근 신청·최근 완료 시각과 종료 당시 대기/진행/완료 수를 보관한다. 자동 종료 시각은 실제 정리 작업 실행 시간이 아닌 원래 만료 기한이다.
- 종료 당시 남아 있는 신청의 닉네임, 장비 종류·시작/목표·수량, 마지막 처리 상태, 접수 시각과 수정 횟수를 함께 보관한다. 신청 상세는 20건 단위 JSON 페이지로 저장하고 펼쳤을 때만 조회한다. 종료 전에 거절·철회로 삭제된 신청 및 이미 삭제된 과거 대장장이는 복구하지 않는다.
- SQLite의 BEFORE DELETE 트리거에서 이력을 저장한 뒤 원본과 닉네임 예약을 외래 키로 삭제한다. 이력 저장 실패 시 종료 전체가 롤백되어 원본 신청을 잃지 않는다. 이력에는 진행자·신청자 인증정보나 생성/신청 IP 해시를 복사하지 않는다.
- 종료 이력은 활성 정원과 이름 예약에서 제외한다. 기존 진행자·신청자 권한으로는 이력에 접근할 수 없으며 사이트 관리자 세션으로만 조회한다. 모든 응답은 no-store다.
- 종료 시각부터 정확히 3일이 지나면 API 조회에서 즉시 제외한다. 각 환경 정리 Worker가 5분마다 최대 100개 만료 이력과 연결된 JSON 페이지를 삭제한다.
- 배포 순서는 두 신청 DB에 `0009_closed_history.sql` 적용, 각 정리 Worker 배포, Pages 배포다. 가격 DB는 변경하지 않는다.

## VM 운영 전환 (2026-11-03)

운영은 `/starforce-api`, 프리뷰는 `/starforce-preview-api`로 직접 조회한다. 저장소·관리 키·CORS 허용 origin은 환경별로 분리한다. 아래의 D1/예약 Worker 배포 설명은 이전 구조의 복구용 기록이며 정상 배포 시 실행하지 않는다. 대장장이 DB는 SQLite WAL/FULL이며, 시간별 온라인 백업을 24시간 보관한다. 운영 전환 시 D1 종료 이력 3건을 보존했고 무결성과 백업을 검증했다.

대장장이 찾기는 단회용 Turnstile `inbox_lookup` 토큰을 포함한 POST 요청만 허용한다. 서버는 action과 정확한 배포 호스트를 검증한 뒤 이름 조회를 실행하며, 토큰 없는 GET 조회는 허용하지 않는다. 실패한 찾기도 요청 제한을 적용한다.

활성 대장장이 생성은 IP당 1개로 제한한다. 시크릿/새 브라우저와 동시 생성도 같은 원자적 INSERT 조건을 적용하고, 일시 중지된 대장장이도 활성에 포함한다. 종료·만료 후에는 다시 생성할 수 있다. 기존 브라우저의 응답 유실 복구 및 이미 존재하는 대장장이 관리는 유지한다. 같은 공인 IP의 기기는 생성 한도를 공유하며, IP가 달라진 사용자를 같은 사람으로 식별하는 기능은 아니다.
